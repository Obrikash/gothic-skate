### Pose and input lock
- oCNpc::SetMovLock 0x7380B0 / IsMovLock 0x7380E0: bit 0x20 of [npc+0x75C]. The engine sets it for documents, trading, containers and dialogs (oCInformationManager::Update sets it only while a dialog runs).
- oCAIHuman::Moving 0x69B9B0: if IsMovLock, it skips CheckMobInteraction, PC_CheckSpecialStates and _WalkCycle and tail-calls oCAniCtrl_Human::_Stand 0x6B7490. So under the lock, W/A/D/Space no longer drive Gothic walking, turning or jumping.
- _Stand reacts only to the controller's own states (_s_walkl, _t_walk_2_walkl, _s_walkbl, _s_aim, _s_walk, _s_jumpup). When the stand state _s_walk is active it calls SetCollDetStat(1)/SetCollDetDyn(1) and SetBodyState(0). Earlier rides very likely had their collision-off undone each frame by this. With S_SLIDE replacing the stand animation, that branch does not run.

## Single-press F8 with a warm worker (built and installed, not run in game)

The user asked for skating to work by pressing F8 alone, with no waiting.

- Worker protocol, from pinned BullySkate src/skate_worker.rs: command 1 (and 6) runs select_world(mount_area, world_phase), relocates and publishes. Command 2 steps input; command 3 unmounts but keeps the process. Any command error sets ready=3 and the worker exits (except "No skating collision" on a mount). The worker opens assets/world.bmgeo and world.bmrails relative to its working directory and loads area 0 at startup. skate-runtime select_world reloads the map from disk and calls physics.replace_map whenever the area or phase changes.
- Design: the bridge starts the worker in the background in the first running world, on an area-0 placeholder floor. On F8 it captures in-process in that frame and writes the collision tagged with a fresh area (cycling 1-127), then sends one mount command with mount_area set. Dismount sends command 3; the worker survives loads and level changes. A failed worker restarts after a cooldown (5 failures disable it for the session). F8 during warm-up queues the mount; F8 again cancels. The mount response timeout is 10 s; other commands keep 1 s.
- The lab moved to %LOCALAPPDATA%\ArcholosSkate\lab (tools/prepare_warm_lab.py; the installer runs it). The x86 game's writes under Program Files can land in UAC VirtualStore, which the x64 worker never reads. The lab holds the hash-checked worker, vcruntime140.dll, fixtures and a source-path.txt pointing at the private owned Skate data.
